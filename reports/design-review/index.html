Game Club Finance redesign

I went through all 12 screens of the live app (signed in as owner, Main Game Club, September 2026 data), plus the login page and the popups. Below: what the new look should be, mockups of the four screens you called out, and every issue I found, page by page.

Direction

Quiet surfaces, loud numbers

The current UI gives every block a card, a tinted background, a coloured icon chip and a sentence of explanation, so nothing stands out. The new look removes most of that. It uses one accent colour, a light sidebar, and large tabular numbers with the currency set small. Colour is kept for meaning: green for money in, red for money out, amber for things that need action. It also adds dark mode. All of this goes into the shared PresentationFoundation components and tailwind.config.ts, so most pages improve without being rewritten.

Mockup 1 · Главная

Dashboard: four numbers first, then detail

The sidebar is grouped by task (daily work, money, management) and shows the club name once. Four KPIs share one strip, and every number fits on one line. Explanations move into tooltips. The payment split becomes a single stacked bar.

Mockup 2 · Вход

Login with a clear way in for new staff

Right now a new employee has no way to know that signing in with Google creates an access request for the owner to approve. The new login page puts Google first and adds a “Нет доступа?” box that explains this in one sentence. It also adds password recovery and moves the language switcher out of the card header.

Mockup 3 · Команда

Team: requests on top, one row per person

Pending requests appear as a single amber strip where the owner picks the club and role and approves in one click. The sidebar shows a count badge, so requests get noticed. Members become a plain table with a role pill and club chips. The page-access details open in a side panel, so the list stays short. The only header button that remains is “Пригласить”.

Mockup 4 · Настройки

Settings: tabs on the left, one save bar

Today the page has two “Сохранить” buttons that stay disabled until something changes, a second language switcher, and a developer-only “Состояние базы данных” card. In the new version, sections are tabs (Клуб, Оплата, Клубы, Профиль). Each setting is a row with the label on the left and the control on the right. A single save bar appears only when something changed. The database check moves behind a “Для разработчика” tab.

Findings

Every issue, page by page

“Bug” means the page is visibly broken. “UX” means it slows people down or confuses them. “Look” means it works but looks dated.

Plan

How I'd roll it out

Every page already uses the PresentationFoundation components, so steps 1 and 2 change most of the app at once. Business logic, Supabase queries and the translation files keep their structure. Any new copy goes into en, ru and uz together.

Step 1

Tokens and foundation

New palette, the Onest font, dark mode, and restyled Button, Card, MetricCard, Field, Modal, DataTable and SegmentedControl.

  • Fixes the washed-out disabled buttons
  • Keeps number and currency on one line
  • Uses one label for the currency: сум
Step 2

App shell

Light, grouped sidebar with one club switcher and a badge for pending requests. Language moves to the profile menu. One PageHeader pattern and one content width on every page.

Step 3

Login, Команда, Настройки

The screens you flagged, built as in the mockups, including the access-request explanation, the approve strip and the tabbed settings.

Step 4

Remaining pages

Dashboard, Касса дня, Закрытие склада, Закупка, Отчёты, Прибыль владельца, Долги, Товары, Зарплаты, each checked at desktop and phone width.
